## 1. Project Overview & Core Philosophy

**newNewton** is a unified, privacy-first, zero-overhead campus enhancer for students of Newton School of Technology (NST). It spans:
1. **Manifest V3 Multi-Browser Extension** (`extension/`) for Chromium (Chrome, Brave, Edge, Arc), Mozilla Firefox, and Apple Safari.
2. **Native macOS App & Interactive WidgetKit Suite** (`macos/`) delivering desktop Glanceable Mess Menus (`.systemMedium`, `.systemLarge`) and Attendance Trackers (`.systemMedium`, `.systemLarge`) with live App Group syncing.
3. **Zero-Overhead Single-Spec Codegen System** (`packages/shared-spec/`) compiling canonical definitions into native ES Modules (`generated-specs.js`) and Swift specs (`NewtonSpecs.swift`).
4. **Clean-Room Supabase LMS Archiver** (`supabase/`) providing:
   - Read-only public assessment discovery via PostgreSQL Row-Level Security (RLS).
   - Deno Edge Function (`supabase/functions/sync-quizzes/index.ts`) using `SUPABASE_SERVICE_ROLE_KEY` to verify submissions directly against Newton LMS (`https://my.newtonschool.co`) before writing to the database.
5. **High-Performance Rust MCP Server** (`mcp-server/`):
   - Stdio JSON-RPC 2.0 server delivering curriculum scope checking, past 10 solved assignment style emulation, pre-submission Judge0 execution, full test grading triage, TypeSafe Jev System One language decision, and browser telemetry mirroring to LLM agents.

## 3. Zero-Overhead Single-Spec Codegen & Build Pipeline (`./build.sh`)

### 3.1 How Codegen Works
All cross-platform constants live in `packages/shared-spec/definitions/*.json`. Executing `./build.sh` runs Bash with guaranteed `jq` to output:
1. **`extension/src/generated-specs.js`** *(written directly into `extension/src/`)*:
   - Exports canonical objects & aliases:
     - `MESS_SPEC` and `MESS_RULES`
     - `ATTENDANCE_SPEC` and `ATTENDANCE_RULES`
     - `COURSE_ALIASES` and `EXACT_COURSE_ALIASES` (flat dictionary mapping full course name -> short alias like `"PSP"`, `"S&AI"`, `"Maths I"`), plus `STOP_WORDS`
     - `THEME_TOKENS`
     - `PLATFORM_CONFIG` and `SUPABASE_CONFIG`
     - Derived constants: `REMOTE_MENU_URL`, `DAYS_OF_WEEK`, `DAY_SHORT_NAMES`, `MEAL_WINDOWS`, `COMMON_ITEMS_SET`, `COMMON_KEYWORDS`, `DEFAULT_ATTENDANCE_TARGET`, `ATTENDANCE_TARGET_OPTIONS`, `PRACTICAL_MARKERS`
   - Exports shared pure helper functions:
     - `shortenCourseName(rawName)`
     - `isSecondaryDish(dishName)`
     - `classifyDish(dishName)`
     - `classifyDishes(dishes)`
2. **`NewtonSpecs.swift`** *(written simultaneously to 3 locations)*:
   - `macos/newNewton/newNewton/NewtonSpecs.swift`
   - `macos/newNewton/newNewtonWidgets/NewtonSpecs.swift`
   - `macos/Sources/Shared/NewtonSpecs.swift`

### 3.2 Why `extension/` Works Directly in Chrome vs. Why `dist/` Exists
- **Why `extension/` works directly**: Because `./build.sh` writes `generated-specs.js` directly into `extension/src/generated-specs.js`, and all files in `extension/src/` are standard vanilla JS / native ES Modules (`"type": "module"`), Chromium can load `extension/` directly as an unpacked extension during development without any build step.
- **Why `dist/` exists (`./build.sh`)**:
  - Minifies JS and CSS with native Go `esbuild` into `dist/extension/` in sub-10 milliseconds.
  - Automatically strips local development origins (`127.0.0.1`, `localhost`) from `host_permissions` in `manifest.json`.
  - Transforms `manifest.json` for Mozilla Firefox (`dist/firefox/`) by adding `browser_specific_settings.gecko` and converting `background.service_worker` to `background.scripts`, then packages `dist/newNewton-firefox.xpi`.
  - Flattens and rewrites relative imports/paths into `macos/newNewton/newNewtonSafariExtension/Resources/` for Xcode's Safari Web Extension target.

### 3.3 Critical Build & Codegen Guardrails
- **NEVER manually edit `extension/src/generated-specs.js` or any `NewtonSpecs.swift` file.** Always edit `packages/shared-spec/definitions/*.json` and run `./build.sh`.
- **Zero-Node / Zero-Deno Runtime Policy**: The project root has no `node_modules`, no `package.json`, and no `deno.json`. All builds execute through native `/bin/bash`, `jq`, and native Go `esbuild` (`/opt/homebrew/bin/esbuild`).
- **NEVER remove `shortenCourseName` or `ATTENDANCE_SPEC.grouping` from `generated-specs.js`**. `background.js` -> `quiz-client.js` -> `attendance/grouping.js` imports `{ ATTENDANCE_SPEC, shortenCourseName }` at module evaluation time. Any missing export crashes both the popup and the MV3 background service worker with `Status code: 15`.

## 4. Browser Extension Architecture & Guardrails (`extension/`)

### 4.1 Classic Scripts vs. ES Modules (Strict Boundary)
- **Classic Scripts (MUST NOT contain `import` or `export` statements)**:
  - `extension/src/telemetry-blocker.js` — Injected into `MAIN` world at `document_start`. Intercepts `fetch`, `XMLHttpRequest`, `navigator.sendBeacon`, and stubs global `Sentry` / `clarity` objects.
  - `extension/src/content.js` — Injected into `ISOLATED` world at `document_start`. Enforces Grauity theme attributes and bridges messages between the page and extension.
  - `extension/src/theme-init.js` — Loaded synchronously in `<head>` of `popup.html` to prevent Flash of Unstyled Content (FOUC).
- **ES Modules (`type="module"`)**:
  - `extension/src/background.js` — MV3 Service Worker (`"type": "module"` in `manifest.json`).
  - `extension/src/popup.js` — Main popup controller.
  - `extension/src/quiz-client.js` — Quiz discovery, 4-tier matching, and Supabase Edge Function client.
  - `extension/src/generated-specs.js` — Codegen output.
  - `extension/src/attendance/grouping.js`, `math.js`, `portal-api.js` — Modular attendance engine.

### 4.2 Safari Web Extension Flattened Bundle Rule (`macos/newNewton/newNewtonSafariExtension/Resources/`)
- Xcode 16's `PBXFileSystemSynchronizedRootGroup` copies every resource file inside `newNewtonSafariExtension/Resources/` flatly into `newNewtonSafariExtension.appex/Contents/Resources/<filename>`.
- If `Resources/` contains subdirectories like `src/background.js` and `src/icons/icon128.png` while `manifest.json` references `"src/background.js"`, Safari fails with `Unable to find "src/background.js" in the extension's resources`.
- **Solution enforced by `./build.sh`**:
  - All extension files are staged **flatly** into `macos/newNewton/newNewtonSafariExtension/Resources/`.
  - Safari's `Resources/manifest.json` uses flat paths (`"background.js"`, `"popup.html"`, `"icon16.png"`, etc.).
  - Relative imports in Safari's JS/HTML copies are automatically rewritten (`../generated-specs.js` -> `./generated-specs.js`, `./attendance/xyz.js` -> `./xyz.js`).

## 5. macOS Companion App & WidgetKit Architecture (`macos/`)

### 5.1 Tri-Directory Swift Synchronization Rule (CRITICAL)
The macOS codebase maintains three directories of shared Swift files:
1. `macos/newNewton/newNewton/` — Xcode Host App target (`newNewton`)
2. `macos/newNewton/newNewtonWidgets/` — Xcode WidgetKit Extension target (`newNewtonWidgetsExtension`)
3. `macos/Sources/` (`Shared/`, `Widgets/`, `App/`) — Standalone CLI build script target (`./macos/build.sh`)

> **Mandatory Rule**: Whenever you edit any shared Swift file, you **MUST copy the updated file to all three locations** so Xcode (`newNewton` + `newNewtonWidgetsExtension`) and `./macos/build.sh` remain 100% identical.

### 5.2 Active macOS Widgets (Only Mess Menu & Attendance Tracker)
`newNewtonWidgetsBundle.swift` registers **only** these three widget configurations:
1. `TodayMessMenuWidget()` (`kind: "com.newton.enhancer.widget.today"`, `.systemMedium` `2x1`)
2. `WeeklyMessMenuWidget()` (`kind: "com.newton.enhancer.widget.menu"`, `.systemMedium` `2x1` & `.systemLarge` `2x2`)
3. `AttendanceWidget()` (`kind: "com.newton.enhancer.widget.attendance"`, `.systemMedium` `2x1` & `.systemLarge` `2x2`)

### 5.3 Cross-Process State Sharing (`PortalDataManager.swift`)
Because macOS App Sandbox can isolate `UserDefaults(suiteName: "group.com.newton.enhancer")` when running unsigned/ad-hoc local builds:
- `PortalDataManager` persists `authToken`, `attendanceTarget`, and `cachedAttendance` across:
  1. `UserDefaults(suiteName: "group.com.newton.enhancer")` & `UserDefaults.standard`
  2. Shared JSON disk state (`newton_portal_state.json`) inside the App Group container and `/tmp/newton_portal_state.json`.

## 6. Standard Workflows & Commands for Agents

### 6.1 Codegen & Multi-Browser Extension Build
```bash
# Run native Bash + jq codegen + native Go esbuild minification + packaging
./build.sh
```

### 6.2 Verifying & Building the macOS App and WidgetKit Extension
1. **Typecheck Xcode Target Sources via `swiftc`**:
   ```bash
   swiftc -typecheck -target arm64-apple-macos14.0 -parse-as-library \
     -framework WidgetKit -framework SwiftUI -framework AppKit -framework AppIntents \
     macos/newNewton/newNewtonWidgets/*.swift
   ```
2. **Build Standalone App & Widget Extension Bundle via CLI**:
   ```bash
   ./macos/build.sh
   ```
3. **Build & Run Full Workspace in Xcode**:
   ```bash
   open macos/newNewton/newNewton.xcodeproj
   ```
4. **Reset macOS WidgetKit Cache**:
   ```bash
   ./refresh.sh
   ```

### 6.3 Building and Testing the Rust MCP Server (`mcp-server/`)
1. **Run Unit and Protocol Tests**:
   ```bash
   cargo test --manifest-path mcp-server/Cargo.toml
   ```
2. **Compile High-Performance Release Binary**:
   ```bash
   cargo build --release --manifest-path mcp-server/Cargo.toml
   ```
